# Needs Product And Reference Review

The v2 workflow is included in upstream source `7759a34`. No actual AIA names,
premiums or benefit terms are seeded or approved by code. Real catalog approval
and publication are separate owner actions; read current CMS data for their
status. See `HANDOFF.md` for deployment evidence.
This is a versioned data/rules workflow, not training a model on customer data.

## Admin Workflow

1. Open Home > Needs calculator > AIA Product catalog & review.
2. Add draft product/reference, edit JSON, then save to draft. Invalid JSON or
   duplicate IDs leave the current saved catalog untouched.
3. Complete TH/EN names, the current official source and validity dates, benefit
   units/bands and every eligibility constraint.
4. Enter reviewer identity and approve the checked record. Approval is disabled
   while required fields are missing or JSON edits have not been saved.
5. Preview through the existing CMS workflow. Publish separately when authorized.

Editing any record content invalidates its approval; re-review is required.
Other records are unaffected. Expired/changed records fail closed on every match.
Revisions, export/restore and draft/live separation are the existing CMS's owners.
The review fingerprint detects edits; it is not authentication. Only existing
authorized CMS writers may change records. Do not put internal documents or
private underwriting notes into this public CMS catalog.

## Product Record

Required fields (new records use blanks, not fabricated product facts):

| Field | Contract |
| --- | --- |
| `id` | Stable lowercase letters/digits/hyphens, unique, max 80 |
| `insurer` | `AIA` |
| `name` | `{th, en}`, real reviewed product name |
| `domain` | `life`, `ci`, `health`, `pa` |
| `benefitBasis` | `all-cause-death`, `next-event-lump-sum`, `annual-medical`, `accident-only`, corresponding to domain |
| `type` | `standalone` or `rider` |
| `salesStatus` | Only `active` can pass; other states remain excluded |
| `distributionAuthorized` | Must explicitly be `true` |
| `source.url` | HTTPS official `aia.co.th` domain/subdomain |
| `source.version` | Document/version identifier |
| `source.verifiedAt`, `source.validUntil` | Valid ISO dates; verified not in future; validity not expired |
| `eligibility.minAge`, `maxAge` | Known integer bounds, 0–100 |
| `eligibility.occupationClasses` | Array of `class1`…`class4`; empty only if reviewed as unrestricted |
| `eligibility.compatibleBasePolicies` | Exact product codes, required nonempty for riders |
| `eligibility.residences` | Nonempty subset of `thailand`, `other` |
| `eligibility.maxIncomeMultiple` | Positive number, or explicit `null` if no such reviewed constraint |
| `eligibility.motorcycleCovered` | Explicit boolean for PA |
| `plans` | One to 100 actual reviewed bands |
| `review` | Set by explicit approval; status/by/at/content fingerprint |

Every plan has `horizonYears` and `premiumMonthly` (integer THB or `null` when
unknown). Do not enter an illustrative premium as an actual quote. Rates varying
by age, occupation or other factors require later quote verification; leave null
unless applicable to the screened band. Unknown premium yields budget-unknown.

Additional plan fields:

- Life/CI: `cover`, next applicable payout in whole THB. Do not put a cumulative
  lifetime multi-pay maximum into a next-event CI benefit.
- Health: `structure:'annual'`, `annualLimit`, `roomPerDay`, `deductible`,
  `copayPercent` (0–100), `territory` (`thailand`/`worldwide`), `opd` boolean.
  Itemised benefit schedules must remain adviser-reviewed, not converted into a
  fake annual total. Nonzero co-pay requires further review before automatic fit.
- PA: `death`, `medical` per episode, `income` over the indicated recovery period.

Eligibility is a preliminary screen, never underwriting approval. Age-at-entry
conventions, medical conditions, exclusions, claim definitions, territory/network
details and premiums still need the real policy/adviser review. No medical history
is collected merely to show candidate names.

Within a product, matching selects the smallest sufficient reviewed band; the
calculated need itself is never rounded to that band. Products explain matching
mechanism, coverage fit and known eligibility. Missing prerequisites are not
silently treated as passing; no commission-based scoring exists.

## Hospital References

Each additional record has `id`, bilingual `name`, integer `daily`, HTTPS
`sourceUrl`, `lastChecked`, `validUntil`, and an explicit `review` generated by
the approval action. Price is room/day, never a treatment package or percentile.
Records must identify comparable included daily items in their name/source.
Only reviewed in-date records appear alongside the existing dated CMS reference.
Do not mix room-only prices and all-in treatment bills.

## Local Verification

`node scripts/needs-v2-check.mjs` uses fictional local fixtures only.
`node scripts/admin-structure-browser.mjs --needs` exercises draft editing,
approval, invalidation and reload with in-memory local storage and blocked
external traffic. These fixtures never populate production or committed defaults.
