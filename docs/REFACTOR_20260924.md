## Source boundaries

- `src/visitor/runtime.js` retains renderer state, lifecycle, routing,
  normalization, public copy projection, and view models.
- `src/visitor/cms-controller.js` owns 49 editor commands: Draft scheduling,
  Save/Publish/Reset, Undo/Redo, repeatable mutations, inline text editing and
  media editing. Its base-class factory accepts explicit schema/cache helpers.
  The host still owns `setState`, normalization, live/draft reads and rendering.
  `editor-history.js` remains the independent history model. The generator
  bundles this real module with esbuild instead of embedding a second history
  implementation. This first extraction does **not** lazy-load the editor UI;
  visitor and editor still use the existing embedded renderer/template.
- `api/ops.js` owns shared identity verification, allowlist/environment checks
  and HTTP responses. `server/cases-handler.cjs` dispatches owner-only Cases;
  `cases-service.cjs` retains transactions, intake and notification behavior;
  `cases-repository.cjs` owns collection selection and the existing complete
  collection reads. No new pagination/index assumptions were introduced.
- `server/legacy-ops-service.cjs` retains legacy Leads/Tasks/Audit compatibility;
  `ops-access.cjs` and `ops-firestore.cjs` own existing permissions and REST
  transport/encoding. Old records, audit history, CAS writes and response
  envelopes stay compatible.
- `covermate-freshness.mjs` owns the separate 30-second server and CDN caches,
  60-second client polling, 5-second minimum request gap, and exponential retry
  delay capped at 300 seconds. These values and their clock origins are unchanged.
- `admin/ops/cases.js` now tracks global summary requests separately from
  filtered list requests. An immediate search no longer discards the in-flight
  summary. A newer full refresh supersedes an older one, leaving the workspace
  invalidates both, and a late summary cannot replace the current filtered rows.

## Regression infrastructure

`scripts/fixtures/ops-portal.mjs` and `scripts/fixtures/cases.mjs` replace tests
reading and evaluating slices of another test's source. Fixtures return fresh
mutable state. Cases emulator records have per-run identifiers, and existing
records are preserved; the suite no longer requires Cases to run first.

`npm run check:refactor` covers fixture independence, the imported CMS controller,
async invalidation/failures/history, Operations boundaries and freshness timing.
It is included in the existing CI gate. Static checks follow moved source owners;
their permission and environment assertions are retained.
